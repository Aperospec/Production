# 导出与实际文件检查

检查交付物是否在本次要求的文件、尺度、变体与使用条件下实际可用。技术检查可发现内容或设计问题，但不能用文件参数合格代替整体质量。

## 对照预期清点实际文件

按当前任务核对文件数量、命名、顺序、尺寸方向、真实格式、语言与尺寸变体、以及要求交付的源文件与元数据。格式以实际编码或文件结构为准，不只看扩展名。

任务没有提供具体规格时，依据用途和已有约定确定可执行输出；不要从本技能带入某平台的默认数值。当前平台或供应商的硬条件需要时从本项目或权威来源核对，写入项目记录。

## 打开或渲染实际输出

对最终交付范围内的每个文件执行能够验证其完整性的打开或渲染，查看是否损坏、内容正确、缺字或字体替换、透明度、裁切、溢出、边缘和其他导出伪影。多页文件不能只看第一页；大量重复输出可用机器检查支持全面覆盖，视觉检查的范围仍须如实说明。

检查目标尺寸、方向、颜色处理、压缩和透明度是否满足当前用途。印刷、屏幕或其他媒介有不同条件，只检查本次需要的项目；需要核对色彩配置或元数据时读取实际文件中的结果，不仅看导出设置；不要仅凭配置名称声称实际色彩已校准。

核对解码后的像素／页面尺寸及文件里的颜色描述、位深、alpha、方向和任务要求的署名／说明等元数据。只改变扩展名、分辨率标签或配置名称不能证明编码或内容已改变；无损重存也未必保留元数据。需要透明度的交付不能误用不承载 alpha 的格式；必须扁平化时使用确定的底色并重查边缘。配置丢失或冲突、印刷 PDF 的检查按 [色彩与印前条件](color-and-prepress.md) 处理。

准确文字与最终画面应对照核验，包括姓名数字、标点、限定、来源、必要标识和页序。文字提取可证明部分内容匹配，不证明显示位置、可读性或遮挡正确。

将解码／结构、文本比对和视觉检查的证据分别解释：可解析不等于可用，文字仍在内容流中也可能被遮罩或页界裁掉。自动比对若忽略空白、归一化字符或依赖 OCR，说明它漏检的变化；精确内容仍对照准确文本和实际画面。核验标准合规需要相应规则与工具，普通 PDF 解析器不能替代指定标准的预检器。

解析器修复告警应定位到实际对象或结构，再判断是否影响本次用途；不能以成功渲染抹去告警，也不因一条告警就断言画面损坏。修复或重写文件后，复验页面、文字、字体资源和相关元数据，保留适用的格式版本；复杂文字提取与源文顺序的检查见 [精确排字](typesetting.md)。

有对应语言版本时，按各自准确文本核对，再比较页义和关键术语、数字与单位、否定、限定、来源及说明的对应关系，尤其检查排版、裁切或漏行是否使一版表达更强或丢掉限制。不同语言无需逐词或同一断行；源文本本身有语义冲突时交回写作核对，不在排字中暗改。

## 在目标条件中判断

按本次用途查看实际尺度与观看距离，需要时检查缩略显示、裁切、界面覆盖、安全区域、压缩、证据可读性或变体。模拟预览不等于真实设备、平台或打印测试；报告实际完成哪一种。

每个变体应保留沟通作用，而不只是尺寸正确。关键对象被裁掉、限定不可读、页序改变或语言变体遗漏，都可能使合法的文件变成不可用的交付。

压缩包交付时，核对内部文件与最终清单及完整性；不能仅检查外部 ZIP 存在。需要可编辑文件时，打开或检视实际结构，区分可编辑文本／层与扁平预览。

## 修复后验证新文件

发现问题时记录具体文件、位置、观察、预期与影响。优先修缺失、损坏、错误内容和无法使用的文字，其次修裁切、可读性、字体及可见工艺缺陷；命名或细节是否必须修复以任务要求和实际后果判断。

修正后的导出必须重新打开或渲染，并核对原缺陷已消失。保留原因不变、只遮住表象的修法不算解决。不要把“重新导出了”当成复查结果。

交付说明只需覆盖当前文件入口、必要顺序、实际检查范围及未解决限制。已通过本地检查不代表已发布、已审核或目标平台已接受；技能不因此新增外部提交权限。
